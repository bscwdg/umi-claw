# UI 点击流覆盖缺口评估（基线 #17 / #18 / #19）

> 日期：2026-09-21 ｜ 结论：**不补脆弱的全链路 UI 点击测试，按"组件接线 + 后端验收"双层覆盖收口，物理点击保留手动。**

## 现状对账

一期 `phase1-e2e.mjs`（真 Electron + CDP，真点击/输入/SSE）已覆盖：
- T2 切换器内联**新建**商家；T3 商家大脑 6 项保存 + **新增**关注词；
- T4 FAQ 录入/入库/检索；T5 Advisor 真问答；
- T6/T6b 雷达交互 + 评分；T7/T7b 热点带去内容中心 → 3 版生成 → 审核流；T8 重新分析；T10 回控制台。

仍**未被物理点击**覆盖的动作：
- 商家**重命名 / 删除**（删除确认弹窗）；
- 关注词**删除**；知识条目**删除 / 重导入**。

## 为什么不补自动化点击
1. 这些动作的**业务逻辑已在后端层被强验收锁定**：
   project.accept 18/18（含改名 conversation_key 不变、删除"先目录后行"、失败不声称成功、current 自愈）；
   business / knowledge accept 各 16/16、23/23（含删除、级联、重导入去重）。
2. **组件接线已逐行核对**（本次复核 `ProjectSwitcher.vue`）：
   - 改名表单复用 create 校验、白名单外字段不发送；
   - 删除走 `ConfirmDialog` 危险确认，调 `store.remove`；catch 中把面板留开并 `switcher.show()` 供重试 —— 与 §十 v1.10 一致；
   - 按钮 busy/disabled 态防重复提交。
3. 唯一缺的"物理点击"主要验证的是**框架本身**（v-model / @click 绑定），不是本项目逻辑；
   为它新增需启动整包的脆弱 CDP 用例，维护成本 > 价值（仓库无 vitest，既有 E2E 已 8 分钟）。

## 残留风险与处置
- 风险：若有人改坏模板绑定（如 @click 拼错），自动化不报。
- 处置：① 绑定类错误在 dev 阶段即肉眼可见；② 已列入发版前手动冒烟清单（建→改名→删商家、删关注词、删知识各点一遍，3 分钟）；
  ③ 若将来引入组件测试框架（vitest + @vue/test-utils），优先把这几个动作作为组件级用例补上，而非走整包 CDP。

**#17 / #18 / #19 的"UI 点击流"子项以本评估收口；各条其余子项（如 lock 漂移、常量双份）维持原状态。**
