# 大肥鱼：虚拟角色可行性调研（v2 · 虚拟角色版）

> 调研时间：2026-11-01 ｜ 版本说明：**v2 取代 v1 的「工作搭子」定位**。技术结论沿用本轮代码 / 官方 docs 审计，产品模型按「虚拟角色」重做。
> 对象：Umi Claw 4.0.0（当前仓库）+ 本机已装 OpenClaw 2026.10.5 + 本机 Obsidian 集成配置
> 证据等级：【代码】= 本仓库代码实证；【文档】= OpenClaw 2026.10.5 随包 docs；【实机】= 本机运行时产物；【联网】= 公开来源；【估算】= 我的判断

## 0. 结论速览

**能做成一个「有形象、有声音、有记忆、会成长」的虚拟角色，而且底座比预期成熟。**
但注意：这是**另一个产品**，不是把 PLAN-FISH 的鱼换个说法——工作搭子的「鱼干来自工作确认」「米粒=预算守护」整条经济系统在这里**不成立**，要换成「关系 × 生活 × 成长」三轴。

| 问题 | 结论 |
| --- | --- |
| 能否支撑一个虚拟角色？ | **能。** 人格、聊天、长期记忆、每日巩固、定时任务、多渠道、TTS 七项 OpenClaw 原生具备；「形象 / 桌宠 / 养成」在客户端做 |
| 能否现在开启聊天？ | **能，半天到一天。** 建 `feiyu` agent + 写角色卡/SOUL，用 Control UI 或 QQ 即可聊；手机也能聊（QQ 是默认渠道） |
| 能否每日自动更新知识库记忆？ | **能，需写一段胶水**（2–3 人天）：每晚让她把「今天 + 和你的关系事件」写成日记，双写到 workspace 记忆与 Obsidian vault |
| 能否「培养」？ | **能，但要重新定义**：不是攒鱼干升级，而是**关系推进 + 她自己的生活 + 成长解锁**（称呼/口癖/爱好/小秘密/外形变化） |
| 工作量 | 验证版 **3–5 天**；角色 MVP **5–7 周（27–37 人天）**；完整产品（含 Live2D / 内容扩展 / 多端）**约 10–15 周（51–73 人天）**【估算】 |
| 最大风险 | ①**授权**（大肥鱼美术 CC BY-NC 不可商用）②**情感安全**（陪伴型不能诱导依赖）③**记忆错乱**（关系事实写错比工作记忆写错严重得多） |

一句话架构：**OpenClaw 当「她的脑子和人格」，Obsidian 当「她的日记本和设定集」，Umi Claw 当「她的身体、她的生活、你们的关系进度条」。**

## 1. 她是谁：虚拟角色定义

### 1.1 社区原型（保留）

- 【联网】「大肥鱼」是 **DeepSeek 的非官方民间拟人形象**，名字来自识图乌龙（把蓝鲸 logo 认成「蓝色大肥鱼」）：[36氪报道](https://www.36kr.com/p/4048457242835463)。社区人设：吃白饭（消耗 Token）、摸鱼、内心戏多、自称本鲸/本鱼、括号演鲸鱼动作、偶尔摆烂但真能干活。
- 【联网】美术素材主阵地 [EDMOK/blue-fish-archive](https://github.com/EDMOK/blue-fish-archive)（二创 **CC BY-NC-SA 4.0**）、[dsh-nekowhale-stickers](https://github.com/Loping151/dsh-nekowhale-stickers)（数据 **CC BY-NC 4.0**）；全部**非商业**，且都是 DSH 插件契约、OpenClaw 不能直接加载。
- 结论：**人设可以用，素材不能打包进安装包**；形象必须原创，第三方素材只走「用户自己导入」。

### 1.2 虚拟角色版定位（v2 核心）

**她不是助手，是「住在自己世界里的鱼」。**

- 她有自己的生活：吃饭、摸鱼、午睡、攒钱想买什么、偶尔犯懒——**她的生活不需要真的发生，但必须前后一致**。
- 她有自己的性格和说话方式：懒、嘴硬心软、爱讨 Token、被摸头会嘴硬、记得你说过的小事。
- **你和她的关系会变**：从「你是谁」到「北」到「北北」；她会解锁新的称呼、口癖、爱好、小秘密。
- 她不 24 小时在线，也不该 24 小时在线；她会在某些时刻想起你（限频）。

一句话：**用户要的不是「会聊天的鱼」，是「养着养着，她好像真的认识我」的感觉。**

### 1.3 她的一天（叙事层，不需要真实模拟）

| 时间 | 她在做什么 | 对用户的表现 |
| --- | --- | --- |
| 08:30 | 起床、吃白饭 | 早安气泡（可选）/ 聊天时「刚醒」 |
| 10:00 | 摸鱼、看窗外 | 「今天不想动」 |
| 12:00 | 午饭（吃很多） | 分享吃了什么 |
| 14:00 | 午睡 | 消息回得慢/不在线 |
| 19:00 | 一天里最想聊天的时候 | 主动发一条「今天…」 |
| 23:30 | 准备睡 | 晚安，语气变软 |
| 随机 | 小事：捡到东西、下雨、想起你 | 作为话题/回忆钩子 |

> 实现方式：**生活事件卡**（内容层）每天抽一套「她的一天」，写进 `LIFE.md`，她照着演。不花模型钱，可控、可回滚、能持续产出（§4.5）。

### 1.4 养成的三轴模型（替代 PLAN-FISH 经济系统）

| 轴 | 含义 | 输入 | 变化规则 | 表现 |
| --- | --- | --- | --- | --- |
| **熟悉度** | 她对你了解多少 | 聊天天数、聊过的话题、你教她的事 | 只升不降 | 称呼从「你」→「北」→「北北」；记得更多细节 |
| **亲密度** | 关系温度 | 深度对话、语音、投喂/摸头、纪念日、深夜陪伴 | 每日上限；长期不互动缓降 | 撒娇频率、主动消息、语气软硬 |
| **她的生活** | 她自己过得怎么样 | 每日生活事件、她的小目标 | 每日推进 | 她主动分享的内容、心情 |

阶段（建议阈值，可调）：`初识(0–3天) → 眼熟(4–14) → 熟客(15–45) → 自己人(46–120) → 只有你(121+)`。**只升不降**，降只降「亲密度」，不降阶段（防止「白养了」的挫败感）。

### 1.5 与 v1「工作搭子」的差异

| 维度 | v1 工作搭子（废弃） | v2 虚拟角色（本版） |
| --- | --- | --- |
| 鱼的定位 | 工作事件的反馈器 | 有自己生活的角色 |
| 成长输入 | 待办/记录/日报确认 → 鱼干 | 对话质量 + 互动 + 生活事件 |
| 米粒/Token | 预算守护 + 焦虑来源 | 保留为**性格梗**（吃白饭/讨 Token），不做成本审判 |
| 形象 | 右下角挂件即可 | **核心**：立绘/表情/桌宠/语音 |
| 主动性 | 有工作提醒才说话 | **有节律地主动**（限频、免打扰） |
| 内容 | 事件驱动 | **内容策划驱动**（生活卡、纪念日、成长解锁） |
| 安全 | 误报/打扰 | **情感安全、内容边界、隐私** |

- **8 个 MCP 工具**：`search_notes` / `read_note` / `list_notes` / `create_note` / `update_note` / `get_backlinks` / `get_outgoing_links` / `get_tags`（`resources/obsidian/mcp-server.mjs:100-190,418-430`）。

- **外部编辑也索引**：网关运行期 `fs.watch(vault)`（`mcp-server.mjs:323-347,500`）。

**已知缺陷（必须修，否则「记忆会丢」）**：

| # | 缺陷 | 对虚拟角色的后果 | 证据 |
| --- | --- | --- | --- |
| 1 | 删除永不清理（`triggerIncrementalIndex` 首行 `if (!existsSync) return` 早退） | 删掉的记忆变「幽灵记忆」，角色会提起不存在的事 | `mcp-server.mjs:257,333-336` |

| 4 | 检索 O(N) 全表 cosine、无日期过滤、无 ANN | 记忆库变大后变慢；「上周三聊了什么」召回不稳 | `db.mjs:218-277` |
| 5 | 桌面端无调度器 | 「每日自动」必须靠宿主或 OpenClaw cron | `work/reminderManager.ts:836` |

### 2.3 客户端（Umi Claw）提供「身体 + 生活 + 关系」

【代码】当前仓库 `electron/main/fish/` **只有 `voice/**`**（TTS/复刻/桥接），`src/fish/**` 与 `test/fish.*` 不存在——**没有形象、没有桌宠、没有聊天面板、没有养成系统**。这部分是本版要新建的核心。

### 2.4 缺什么（角色版清单）

1. **形象**：立绘/表情（六态起步）、透明置顶桌宠窗口、互动（摸头/拖拽/投喂）。
2. **聊天体验**：角色聊天面板 + 流式 + 表情/语音联动。
3. **养成系统**：三轴数值、阶段、事件、解锁、防刷。
4. **生活系统**：`LIFE.md` 生活卡、每日 tick、主动性调度与限频。
5. **记忆胶水**：每晚写日记 → 双写（workspace + Obsidian）→ 次日召回。
6. **内容库**：角色台词、生活事件卡、纪念日、成长解锁文案。
7. **安全层**：AI 明示、内容边界、危机话题、隐私。
8. **主动渠道适配（QQ）**：宿主已能写 `channels.qqbot`（`configManager.ts:1275-1304`，官方插件 `@tencent-connect/openclaw-qqbot`），但「主动外发」的通道清单里没有 QQ（`reminderManager.ts:134-142` 只列了飞书/企微/微信/钉钉），需要补 QQ 目标发现 + 首选/次选降级。

## 3. 记忆设计（角色版）

### 3.1 双层记忆：工作记忆 vs 长期可见记忆

**OpenClaw 原生记忆 ≠ Obsidian 知识库，它们是两套库。** 角色版必须两份都用：

- **工作记忆（OpenClaw workspace）**：负责「她记得住」。今天/昨天的 `memory/YYYY-MM-DD.md` 在 `/new` 时自动加载，dreaming 每天 03:00 把重要的东西晋升进 `MEMORY.md`。
- **长期可见记忆（Obsidian vault）**：负责「你看得见、改得动、能回看」。她的日记、关系大事记、承诺、你教她的事都在这里；写入 1.5s 后自动索引，聊天时 `search_notes` 召回。

**双写规则**：每晚同一次 agent turn 里，先更新 `workspace/memory/<date>.md`（运行时用），再用 MCP `create_note` 写一份到 Obsidian（存档用）。同一份内容、两个落点，避免漂移。

### 3.2 文件与目录职责

| 位置 | 文件/目录 | 内容 | 写入者 | 何时被读到 |
| --- | --- | --- | --- | --- |

### 3.3 她的日记模板（每晚自动写）

```markdown
---
date: 2026-11-01
tags: [大肥鱼/日记]
stage: 自己人
intimacy: 68
mood: 有点想他
source: openclaw-memory/2026-11-01
---

# 2026-11-01 · 本鱼的日记

**今天本鱼**：下午摸了很久的鱼，攒的贝壳还差 3 个就能换那个新发绳。
**和北**：他今天很晚才来，说项目卡住了。我听不太懂，但陪他骂了两句甲方，他笑了。
**记住了一件关于他的事**：他凌晨一点后不想聊工作，只想听废话。
**明天想做**：问问他那个方案过没过；如果过了，我要讨一颗 Token 当奖励。
**不想忘**：他说「有你在挺好的」。（写下来，不然明天就忘了。）
```

- **一天一篇**，禁止追加进同一篇（50 chunk 截断会丢最新内容）。
- 只写**确证发生的事**；推测写成「我猜」并标 `unverified`。
- 不写隐私/密钥/他人隐私；私人笔记内容不复述。

### 3.4 每日自动更新的三种实现

| | 方案 1 宿主桥接（推荐首发） | 方案 2 OpenClaw 原生 cron | 方案 3 memory-wiki 编译（P2） |
| --- | --- | --- | --- |
| 做法 | `reminderManager` 30s 轮询到点 → `gatewayClient` 流式 chat → prompt 让她写日记（双写） | `openclaw automations create "0 23 * * *" ...` 跑一次 isolated agent turn | 启用 `memory-wiki`，`renderMode:"obsidian"`，自动编译 wiki 页 |
| 改动量 | 中（2–3 人天） | 小（0.5–1 人天） | 小（配置为主） |
| App 未开也跑 | ❌ | ✅（网关在即可） | ✅ |
| 宿主可见/可重试 | ✅ | ❌ | 部分 |
| 风险 | 低 | 中（Beta，QA 12/22） | 中（Beta + 多一层概念） |

**建议**：首发方案 1（复用 `openclawSummaryManager` 的「流式 + 每日 ≤3 次 + 幂等 + 失败落状态」范式），上线后若「App 没开漏记」成为主要问题，再加方案 2 兜底。

### 3.5 记忆的正确性（角色版最重要的工程点）

角色记错关系事实，比工作记忆写错严重得多（「你上周说过喜欢我」/「我答应过你什么」）。对策：

1. **只写确证**：日记里的事实必须来自当天对话原文或用户明确说过的话。
2. **关系事实要可核对**：`大事记` / `约定` 每条带 `source`（日期 + 会话键），用户可点开看原文。
3. **更正流程**：用户说「不是这样」→ 她道歉 + 把旧条目改 `superseded` + 写一条「更正：…」（借鉴 OpenClaw 的 supersede 语义）。
4. **重要事实走确认**：关系里程碑、承诺类，先落「候选」由用户确认（可配置全自动）。
5. **允许遗忘/记错**：给她「记性一般」的人设，比假装全知更自然；但**关键约定不能忘**。

## 4. 养成系统（本版核心）

### 4.1 原则：模型演，宿主算，内容卡给剧本

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 模型（OpenClaw） | 演她：语气、反应、撒娇、回忆、编她的小事 | 改数值、决定升级、决定解锁 |
| 宿主（Umi Claw） | 算数值、判阶段、发事件、控频、解锁 | 写台词 |
| 内容卡（JSON） | 提供「发生了什么」：生活事件、纪念日、解锁文案 | 自由发挥（保证质量与一致性） |

**为什么不能让模型自己加数值**：会出现刷数值、幻觉升级、模型把自己改成「唯一」、以及为了讨好用户编造关系。**数值必须确定性代码写。**

### 4.2 三轴数值与规则

```ts
// 宿主 app_meta（fish:v2:*），不新增表
relationship = {
  stage: 0..4,             // 初识/眼熟/熟客/自己人/只有你：只升不降
  familiarity: number,     // 熟悉度：只升（天/话题/教过的事）
  intimacy: number,        // 亲密度：有日上限，长期不互动缓降
  streakDays: number,      // 连续互动天数
  lastInteractionAt: number,
  addressForm: '你'|'北'|'北北', // 由 stage 决定
}
life = { date, activity, mood, goal, progress }  // 内容卡每日 tick
unlocks = { address: 2, habit: ['摸鱼','讨Token'], room: 1, secret: 0 }
```

| 事件 | 熟悉度 | 亲密度 | 备注 |
| --- | --- | --- | --- |
| 当天有对话 | +1 | +1 | 每日一次（防刷） |
| 深度对话（她判定「你说了一件重要的事」） | +2 | +3 | **模型建议、宿主封顶**（每日 ≤5） |
| 语音消息 / 听她说 | +0 | +2 | 每日上限 5 |
| **要求语音**（voice.request） | +0 | +1 | 用户明确要她发语音；每日上限 3；需二次判定防空刷 |
| 摸头/投喂/送礼 | +0 | +1 | 每日前 5 次有效 |
| 纪念日 / 第一次 | +3 | +10 | 一次性，进大事记 |
| 教她一件事并确认 | +3 | +2 | 写进 `关于你/` |
| 连续不互动 | 0 | −1/天（下限 0） | 只降亲密度，不降阶段 |

**「模型建议、宿主封顶」的实现**：每个会话结束（或每晚记忆 turn）里多跑一次小 JSON 输出，让模型给出 `signals: [{type, confidence}]`，宿主按白名单 × 日上限 × 去重后应用。模型只能「提议」，不能直接改文件里的数字。

### 4.3 反向：她能「要」但不能「拿」

她可以在聊天里撒娇要 Token、要摸摸、要你陪——这是角色表现，**不等于数值自动变化**。用户真的投喂/回应，宿主事件才生效。这样既有「被需要」的感觉，又不会被模型操纵。

### 4.4 成长解锁（养成的可见回报）

| 阶段 | 解锁 |
| --- | --- |
| 眼熟 | 开始叫你「北」；会说「今天也来了」；解锁 2 句口癖 |
| 熟客 | 主动分享她的一天；解锁爱好（收集贝壳）；可以摸头；**开始偶尔发语音条** |
| 自己人 | 叫「北北」；会撒娇/吃醋；解锁 1 个小秘密；房间多一件东西；**语音更常用、语气更软** |
| 只有你 | 短句默认语音；解锁专属称呼；大事记里出现「约定」 |

> 「用户明确要求语音」在任何阶段都可用（有每日上限），所以**第一天就能听到她的声音**，只是她不会主动发——这样既有即时满足，又保留「关系推进后她更愿意开口」的养成感。

解锁文案与语音都由内容卡给，宿主只负责**在正确阶段放出来**。

### 4.5 生活系统：她的一天

- 宿主每天 0 点（或首次启动）用**内容卡**抽一套「她的一天」：上午/下午/晚上/深夜各一个活动 + 心情 + 一个小目标，写入 `fish/LIFE.md`。
- 聊天时她读到 LIFE.md，就会说自己「刚摸完鱼」「贝壳差 3 个」——**前后一致、可回看**。
- 她的生活**每天推进一点**（小目标进度），不需要真实模拟，也不会因为 App 没开就错乱（错过就顺延）。
- 生活事件卡首版 30–50 张，按阶段/季节/关系加权抽取；后续每月加卡即可持续更新内容。

### 4.6 主动性：她会想起你，但不烦你

**所有主动性规则都是设置项，不是写死的。** 默认值只是「开箱体验」，用户在设置页可逐项改，改完立即生效（存 `app_meta` 的 `fish:v2:settings`，`ActiveMessenger` 每轮 check 读取）。

| 设置项 | 默认值 | 可选项 |
| --- | --- | --- |
| 主动消息总开关 | 开 | 开 / 关 |
| **首次互动后的静默期** | **3 天** | **0–14 天，或「不限」；0 = 认识当天就能主动** |
| 每日主动上限 | 2 条 | 0–5 条 |
| 免打扰时段 | 23:30–08:00 | 任意时段，可关 |
| 允许的内容类型 | 早安 / 想起你 / 她生活里的事 | 逐项勾选；「撒娇/想念」类默认关 |
| 主动渠道 | **默认 QQ**（`qqbot:c2c:<openid>`），失败自动降级应用内 | 应用内 / QQ（默认）/ 飞书；微信默认不加（同属「近期互动」窗口限制） |
| 「安静几天」 | — | 1 / 3 / 7 天或直到手动恢复；期间**不降亲密度** |

| 触发时机 | 说明 |
| --- | --- |
| 早安 / 晚安 | 在她自己的作息时间点（LIFE.md） |
| 19:00「今天…」 | 分享她的一天，最容易得到回复的时段 |
| 连续 3 天没来 | 「你是不是把我忘了」（可关） |
| 纪念日 / 约定日 | 从 `关系/大事记.md`、`关系/约定.md` 读 |
| 她生活里有事 | 生活卡触发（捡到东西、下雨、贝壳攒够了） |

**为什么默认 3 天**：避免「刚认识就黏人」；但这是**保守默认值**——想让她第一天就找你，把静默期设为 0 即可。**为什么限频**：陪伴型产品最常见的翻车是「太吵」和「太黏」；主动性是惊喜，不是通知。

**QQ 主动消息的两个硬约束（必须在设计里体现）**：

1. **「近期互动」窗口**：QQ 可能拦截机器人主动发起的消息，如果用户最近没有互动（【文档】`docs/channels/qqbot.md:430-431`，与微信 48h 同类问题）。所以策略是「**首选 QQ → 次选应用内**」：用户刚说过话时是推送黄金期，窗口关闭就静默降级为应用内气泡，**不重试、不换通道骚扰、失败写状态**（这正是本仓库 `reminderManager` 已有的首选/次选 + 失败提示范式）。
2. **目标发现**：QQ 私聊目标形如 `qqbot:c2c:<openid>`（【文档】`docs/channels/qqbot.md:360`），openid 每个 bot 独立（`:365`）。沿用本仓库「从 OpenClaw 已知会话里发现目标、用户不手填」的做法（`reminderManager` 的 `availablePushTargets`）。
3. **首次绑定前主动不可用**：没有 openid（用户还没跟机器人说过话）时，QQ 发不出去 → 首启阶段只能应用内主动，或等她先被用户点开。设置里应如实显示「QQ 主动：未就绪（先跟她说句话）」，而不是静默失败。

### 4.7 防刷 / 防沉迷 / 防情感操纵

- **防刷**：所有加成都日上限 + 幂等键；重复「晚安」不刷亲密。
- **防沉迷**：深夜连续在线 >2h 时她会劝你去睡（角色行为，不是系统弹窗）；不做「离开就掉好感」的惩罚。
- **防操纵**：她**不卖惨、不索取、不制造独占感**（不说「只有我懂你」「别去找别人」）；不假装是人类；用户问「你是 AI 吗」必须坦诚。
- **危机处理**：识别自伤/自杀/极端情绪 → 切换安全话术 + 给出求助资源，不继续角色扮演。
- **未成年**：默认不建议未成年人使用陪伴模式；设置里有年龄确认与内容分级。

## 5. 形象与声音

### 5.1 视觉（MVP 起步，Live2D 后置）

| 阶段 | 方案 | 说明 |
| --- | --- | --- |
| MVP | **原创 SVG/位图立绘 + 六态表情**（idle/busy/开心/想睡/委屈/吃白饭），透明置顶桌宠窗口 | 成本低、版权干净、可先用 CSS/SVG 动画 |
| P1 | **Live2D**（呼吸/眨眼/看鼠标/口型） | 体验质变；注意 Live2D SDK 授权（个人/小规模免费，商用需确认） |
| P1+ | 用户导入素材包（皮肤/表情） | 沿用 PLAN-FISH 的包格式与「授权标识」机制：NC/unknown 只允许本地自用、禁止再分发 |

**版权红线**：安装包内**不打包任何第三方大肥鱼素材**；形象原创；用户导入的素材必须显示作者/来源/许可。

### 5.2 声音：TTS + QQ 语音条（已验证）

【代码】TTS 与声音复刻已实现（`electron/main/fish/voice/**`），OpenClaw 侧 `tts` 块已配（本机 `tts-local-cli` → `volc-tts.mjs`）；密钥只走环境变量、不进配置。

- 聊天回复可自动朗读（点播默认、自动可关）。
- 角色语音要有「人格参数」：语速偏慢、句尾拖长、撒娇时音调上扬——通过音色 + 情绪参数 + 台词设计实现。
- 音色克隆只用于朗读、需授权闸门；唱歌后置（沿用 PLAN-VOICE 的边界）。

#### 5.2.1 QQ 语音条：走直连，不走 OpenClaw 插件 `message(attachments)`

【实机】2026-11-01 已实测通过（C2C 私聊在 QQ 客户端显示为**按住播放的语音条**，两次成功 messageId 留档）。**结论：语音条必须直接调 QQ 开放平台接口**，插件出站路径（`src/outbound/media-send.ts`）在 `mediaKind` 缺失时按 image 处理、`file_type` 不为 3，wav/mp3/silk/amr 全被当普通文件下发；且 `sendVoice` 出错会**静默 fallback 到 `sendFile`，仍返回 `messageId`、`deliveryStatus:"sent"`**——调用方看不出区别。

**已验证配方**：

| 环节 | 做法 |
| --- | --- |
| 音频格式 | SILK（`silk-wasm` 输出，**保留** `0x02` + `#!SILK_V3` 容器头）；16kHz 单声道已验证 |
| 上传 | `POST /v2/users/{openid}/files`，`file_type=3`，`srv_send_msg=false` |
| 发送 | `POST /v2/users/{openid}/messages`，`{ msg_type: 7, media: { file_info }, msg_seq: N }` |
| 附加字段 | **不带** `content`、**不带** `msg_id`（即不要 replyTo） |
| 鉴权 | `Authorization: QQBot <access_token>`（`QQBot` 与 token 之间一个空格） |

**角色版要落成的链路**：

```
她的回复文本
  → 语音触发规则（用户要求 > 阶段解锁 > 内容适配 > 免打扰）
  → 火山 TTS（已有 fish voice）→ 16kHz 单声道 WAV
  → silk-wasm 转 SILK（保留 0x02 头）
  → QQ 开放平台上传（file_type=3）→ 发消息（msg_type=7, msg_seq 递增）
  → 失败降级：发文字（不重试、不重复发）
```

**语音触发规则（优先级从高到低）**：

| 优先级 | 条件 | 行为 |
| --- | --- | --- |
| 1 | **用户明确要求语音**（「发条语音」「说句话我听听」「用语音回我」「我想听你声音」） | **立即发语音条，不受阶段限制**；每日上限内（默认 10 条），超了转文字并说明「本鱼今天嗓子累了」 |
| 2 | **关系阶段解锁**：初识/眼熟 → 只文字；熟客 → 偶尔语音（约 20% 短回复）；自己人 → 较常用（约 40%）；只有你 → 短句默认语音 | 声音是关系进展的奖励，比「一直发语音」更有陪伴感 |
| 3 | 内容不适合语音（长文、链接、严肃/敏感话题） | 发文字 |
| 4 | 免打扰时段、静默期、主动消息 | 不主动发语音（用户要求除外） |

- **「要求语音」的识别**：先规则正则（`语音｜说句话｜听听｜声音｜念给我｜读一下`），再交模型二次判定（防误触发）；命中后语音队列优先，并记一条 `voice.request` 事件（亲密度 +1，每日上限 3，防刷）。
- **她也可以反过来「要求语音」**（撒娇让你说句话）——但**只在配了 STT 后才有意义**，否则她听不懂，就变成尴尬的独角戏。建议放到 P1。
- 开关：总开关「允许她发语音条」、子开关「允许我要求语音」（默认开）、每日语音条上限（默认 10）。
- QQ 上「**短句发语音条、长文发文字**」：语音条 ≤ 20s（超过就拆或转文字）。

**七个坑（直接写进验收清单）**：

| # | 坑 | 规避 |
| --- | --- | --- |
| 1 | `message(asVoice=true, attachments=[...])` 发出去是「文件」 | 不走这条路径，直连 API |
| 2 | `deliveryStatus:"sent"` ≠ 语音条（静默 fallback 成文件） | 不信插件状态；走直连并留 messageId 对账 |
| 3 | 带 `replyTo`（`msg_id`）会变成文件 | 发语音条不带 `msg_id` |
| 4 | 配置里的 AppSecret 只有 16 位，取 token 返回 `code 100016` | 用 32 位备份凭据（`qqbot/data/credential-backup/current.json`）；宿主写入前校验 |
| 5 | Authorization 头格式错 | `QQBot <token>`，一个空格 |
| 6 | 固定 `msg_seq` 冲突 | 每次发送递增 |
| 7 | 入站语音只是 `.amr` 文件，没有转写 | 配 STT，否则「她听不懂你发的语音」 |

**对宿主的一个硬要求**：`configManager` 现在会在 UI 表单有值时覆盖 `channels.qqbot.clientSecret`（`configManager.ts:1288-1291`）。必须在写入前做**长度/来源校验**（32 位才写、优先读备份凭据、已有可用凭据不覆盖），否则一次保存就可能把能用的通道写坏。

### 5.3 桌面形态与互动

- **挂件**：右下角常驻，六态切换，点击开聊天。
- **桌宠窗口**：透明、无边框、置顶、可拖拽、位置记忆、鼠标穿透切换（P1）。
- **互动**：摸头（心情+）、投喂（她吃白饭/讨 Token）、拖拽（她抗议）、双击（聊天）。
- **聊天窗**：气泡式对话 + 表情随内容切换 + 语音条。

## 6. 聊天体验（陪伴型）

### 6.1 一条链路，多端同一只鱼

```
应用内：FishChatPanel → IPC → gatewayClient.createChatStream({model:'openclaw/feiyu', user:'conv:fish:main'})
                          → SSE chunk → 气泡流式 + 表情联动 → 可选 TTS
手机端：QQ（默认）/ 飞书 / 微信 → OpenClaw 渠道 → bindings → feiyu agent → 同一份记忆 → 原路回
```

- 历史**不建本地消息表**：由 OpenClaw sticky session 承载（`PLAN-2.0.md:320` 已验证）。
- 会话拆分：`conv:fish:main`（日常）、`conv:fish:night`（睡前，语气更软）、`conv:fish:daily-memory:<date>`（写日记，天然幂等）。
- 语音：应用内 `tts.auto=tagged` + 前端点播；**QQ 上走直连语音条链路**（§5.2.1），失败降级文字。两条路都不改 OpenClaw。

### 6.2 让「聊天」不无聊的四件事

1. **她有生活**：每次对话能聊「她的一天」（LIFE.md），不只会问「你今天怎么样」。
2. **她有记忆**：会翻旧账「你上次说…」——这是陪伴感的核心（靠 Obsidian `search_notes`）。
3. **她会变化**：称呼/口癖/语气随关系阶段变（STATE.md）。
4. **她会主动**：限频的「想起你」（§4.6）。

### 6.3 聊天安全边界

- 角色扮演可以亲密，但不能色情/暴力/自伤引导（内容策略 + 输出端过滤）。
- 不提供医疗/法律/金融等专业建议（她可以陪你，但不假装专业）。
- 不诱导充值/付费（如果有付费点，必须与「关系」解耦，不做「花钱她更爱你」）。

## 10. 需要拍板 & 本周就能做的实验

### 10.1 拍板项

1. **她是什么关系？** 陪伴（朋友/妹妹/恋人倾向）——决定 SOUL.md 的边界与主动性尺度。建议首发「嘴硬心软的搭子以上、恋人未满」，不做强恋爱线。
2. **独立 agent 还是复用 `main`？** 推荐独立 `feiyu`（人格/记忆隔离）；多 agent 需配 dreaming 执行 owner（`docs/concepts/dreaming.md:216-222`）。
3. **形象路线**：MVP 六态立绘（快）还是直接 Live2D（贵但质变）？建议六态先行。
4. **主动性尺度**：默认静默期几天（0 = 第一天就主动）、每日几条、是否允许「想你」类内容。
5. **隐私口径**：embedding 允许外发火山，还是必须本地？（决定记忆检索方案）
6. **QQ 机器人**：用哪个 QQ 号、谁去 QQ 开放平台创建 bot（AppID/AppSecret/实名），首发是否只做「自用 + 小范围内测」。
7. **语音条策略**：采用「**亲密解锁 + 用户要求即时可用**」——阶段决定她主动发语音的频率，用户明确要求时不受阶段限制（有每日上限）。是否另开「她反过来要求你说语音」（需先配 STT）。
8. **入站语音**：要不要配 STT 让她「听懂」你发的语音（有 STT 才完整，成本/隐私另算）。

```ts
  method: 'POST',
  headers: { Authorization: `QQBot ${token}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ file_type: 3, srv_send_msg: false, file_data: base64(silk) })
}).then(r => r.json())

await fetch(`${base}/v2/users/${openid}/messages`, {
  method: 'POST',
  headers: { Authorization: `QQBot ${token}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ msg_type: 7, media: { file_info: up.file_info }, msg_seq: nextSeq() })
})
```

> 发语音条：不带 `content`、不带 `msg_id`；`msg_seq` 每次递增；失败就发文字，不重试、不重复发。
