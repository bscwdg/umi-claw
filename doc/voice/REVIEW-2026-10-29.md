## 二、P0 问题

### P0-1 对话内语音（OpenClaw）用 Agent Plan Key 很可能 401

- `electron/main/fish/voice/core/openclawTts.ts:71-80` 把应用里的 TTS Key 注入为 `VOLCENGINE_TTS_API_KEY`。
- `electron/main/clawManager.ts` 在网关启动时把该环境变量传给 OpenClaw。
- 但 OpenClaw 的 `volcengine` provider 默认走标准接口 `https://openspeech.bytedance.com/api/v3/tts/unidirectional`，注入的 `tts` 块没有 `baseUrl`（`openclawTts.ts:57-68` 只写 `auto/provider/resourceId/speakerVoice`）。
- 实测：用现有 Agent Plan Key（`ark-...`）请求标准接口 `POST /api/v3/tts/unidirectional`（resource `seed-tts-2.0`）返回 **HTTP 401**；同一把 Key 在 Plan 接口 `/api/v3/plan/tts/unidirectional` 才是 200。
- 影响：用户在 `/voice` 打开「对话内语音（OpenClaw）」后，重启网关，预设音色的 `/tts` 很可能直接鉴权失败；界面看起来配置成功，实际不出声。
- 建议：对话内语音改用**语音控制台 Key**（与克隆 Key 同一产品线），或给 OpenClaw 注入带 `baseUrl` 的 Plan 端点并实测其响应解析；同时在 `/voice` 增加「测试对话内语音」按钮。

### P0-2 注入 `tts` 块是整段替换 / 整段删除

- `electron/main/configManager.ts:1334`：`existingConfig.tts = ttsCfg`（整段替换）。
- `electron/main/configManager.ts:1336`：`delete existingConfig.tts`（关闭或没有 Key 时整段删除）。
- `electron/main/fish/voice/core/manager.ts:206-215`：`conversationTts === 'off'` 或缺少 Key 时返回 `null`。
- 影响：用户在 OpenClaw 里已有的 `tts.personas`、其他 provider、fallback、手写配置会被覆盖；关闭应用语音时会把用户自己的 OpenClaw TTS 配置删掉。下次 `syncOpenClawConfig` 就发生。
- 建议：只合并/删除应用自己管理的字段（如 `tts.auto`、`tts.providers.volcengine`），保留 `personas`、其他 provider 与未知字段；关闭时只移除 `providers.volcengine`，不要 `delete existingConfig.tts`。

### P0-3 改完设置不会自动重启网关，环境变量只在启动时注入

- `electron/main/index.ts:1967` 的 `onSettingsChanged` 只调用 `configManager.syncOpenClawConfig()`。
- `clawManager.setVoiceTtsEnvProvider()` 只在网关**启动**时读取 env（`clawManager.ts` 启动段）。
- 影响：用户切换「对话内语音」或换 Key 后，运行中的网关仍是旧环境；必须手动重启 OpenClaw。UI 在 `VoicePage.vue:284` 写了「改完需重启网关生效」，但没有状态提示/一键重启，容易以为没生效。
- 建议：保存后提示「需重启网关」并提供重启按钮/状态；或在设置变更后自动重启（需用户确认）。

## 三、P1 问题

1. **2.0/1.0 没有本次 OpenClaw 适配**：`release/2.0`/`release/1.0` HEAD 仍是旧版，无 `openclawTts.ts`、四接口、远端对账。若三版本都要有，需把 `fa7ee37` 移植过去。
2. **对话内语音与自动朗读是两套路径**：`autoSpeak` 由应用主进程直接合成并推给窗口；`conversationTts` 交给 OpenClaw。两者都开时，本地提醒与渠道回复可能各自出声；没有互斥/去重提示。
3. **网关不是本应用拉起时没有 Key**：`setVoiceTtsEnvProvider` 只影响 `ClawManager.start()`；用户直接用外部 OpenClaw 启动，`VOLCENGINE_TTS_API_KEY` 不会注入，`/tts` 无 Key。
4. **`tts` 块缺少 `personas`/fallback/provider 细节**：只写最小字段，覆盖后 OpenClaw 侧原有语音人格/降级链丢失（与 P0-2 同源）。
5. **测试覆盖**：18/18 都是 mock/纯函数，未覆盖「真实网关 + `/tts`」和「标准接口 401」路径；P0-1 只能靠实测发现。
6. **克隆远端对账**：V18 覆盖四态判定，但没有真实供应商删除/过期后的端到端验证；7 天过期本地已阻断。

## 四、使用说明（按当前 UI）

入口：左侧「管理」组 →「语音设置」→ `/voice`。四个 Tab：概览 / 供应商与密钥 / 音色 / 预算与缓存。

### 1. 两把 Key

| Key | 用途 | 来源 |
| --- | --- | --- |
| Agent Plan TTS Key | 应用内预设音色合成（Plan 接口 `/api/v3/plan/tts/unidirectional`） | 方舟 Agent Plan |
| 语音服务 Key | 克隆训练、克隆音色合成（标准接口 + `seed-icl-2.0`） | 火山语音控制台，需开通声音复刻 |

界面只显示尾号；密钥走 `safeStorage`，不写 `openclaw.json`、不进日志。

### 2. 音色与参数

- 默认音色：450 条豆包 2.0 音色（中文 + 外语），默认 Vivi 2.0。
- 情绪：按官方枚举下拉；预设音色支持情绪，克隆音色按官方文档不传情绪。
- 语速 0.2–3.0。
- 高级：预设 TTS / 克隆合成 / 克隆训练 / 克隆查询四个 endpoint + 两个 Resource；域名固定 `openspeech.bytedance.com`，防止 Key 外发。

### 3. 自动朗读 vs 对话内语音

- **自动朗读**（应用内）：off / tagged / always，只影响应用自己的提醒气泡/通知，直接播放本地音频。
- **对话内语音（OpenClaw）**：off / tagged / inbound / always，写入 OpenClaw `tts` 块，由网关在聊天回复时发声；**保存后需重启网关**。
- 现状：对话内语音的预设音色用 Agent Plan Key，标准接口 401（P0-1），建议先不要把它当作可用功能，或改用语音控制台 Key。

### 4. 克隆流程

1. 选 15–30 秒、单人、干声、无背景音乐的样本（≤10MB，wav/mp3/ogg/m4a/aac/pcm）。
2. 勾选授权确认，填名称/语言/样本文本。
3. 训练（后付费 `custom_speaker_id`）；轮询状态；下载试听（1 小时有效）。
4. 「确认并转正」会收取槽位费，二次确认；转正后 ID 不能再次复刻。
5. 7 天未转正会被自动删除；本地已阻断过期音色的转正与合成。
6. 转正后可「设为默认」，应用内朗读与 OpenClaw 对话语音都会用该音色（后者仍需网关支持）。

### 5. 通道差异

- WebChat：音频附件。
- 飞书：Ogg/Opus + `im:resource:upload` 才能出原生语音条。
- 微信：插件 2.4.10 只有文件附件，没有语音条。

## 五、建议修复顺序

1. P0-1：对话内语音改用语音控制台 Key，或补 `baseUrl` + 适配验证；加「测试对话内语音」。
2. P0-2：`tts` 块改为合并，不整段替换/删除。
3. P0-3：保存后提示/提供重启网关，或自动重启。
4. 把 `fa7ee37` 移植到 2.0/1.0。
5. 增加真实网关 `/tts` 冒烟（至少一次预设音色、一次克隆音色）。
