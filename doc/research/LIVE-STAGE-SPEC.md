# 直播展示页（Live Stage）规格草案

> 来源：用户提供的两张手机截图（2026-11-01）——大肥鱼拟人成「虚拟员工」在直播间上班。
> 定位：**M3 模块**，M1（角色本体）完成后做；不阻塞基础功能。本文只冻结 UI/数据/技术方向，细节随 M3 再定。

## 一、截图里有什么

竖屏直播画面（手机截图 9:16 比例），从上到下：

1. **今日工资** `900 / 6,000`（右侧 `15%`，下方进度条）。
2. **统计行**：`专注 15 分钟 · 白干 17 次 · 被抓 1 次`；右侧时钟 `周日 03:50:55`。
3. **状态行**：绿色胶囊 `专心工作中`；`⚡ 手速 ×2.8`；`员工守则` + 白色规则条（如「赚够token就能合法摸鱼」「摸鱼就会白干」）。
4. **倒计时环**：黄色/绿色圆环，中间 `2 秒` / `15 秒`。
5. **左侧监视器**：深色代码窗口（标题 `…js — Douglas Code`），滚动显示代码。
6. **右侧/中央**：Q 版大肥鱼坐在电脑前（女仆头饰、蓝长发、红发卡），姿态随状态变化（第 1 张专注、第 2 张犯困托腮）；桌上杯子、键盘、鼠标。
7. **底部弹幕条**：白色胶囊 `💬 @讴嘿：哈基米` / `@宇智波佐助「须佐能乎」：还不睡觉？`。
8. **字幕台词**：`（嘀咕）哈基米？我还哈基鱼呢，别乱起名。`
9. **右下角**：`退出清屏` 按钮。

## 二、产品定义

**大肥鱼的「打工直播」模式**：她坐在工位上干活（专注/摸鱼/被抓），观众发弹幕，她用字幕（可配语音）回应；「工资」把 Token/产出可视化，制造直播张力。

- 它**不是**新的人格，而是角色本体的一个「舞台视图」：关系、生活、语音、记忆都复用 M1。
- 默认不对外直播，先做**本地舞台页**：自己能看、能截图、能推流。
- 观众互动先做「本地注入」（手动/脚本），平台弹幕接入放后。

```
│ ┌──────────────┐   ╭───╮   ┌──────┐ │

│                                      │
│   💬 @观众：弹幕内容                  │ y 1250–1400

│                                      │

```

- 用 `transform: scale()` 适配窗口；所有元素用绝对定位 + 百分比，保证 1080×1920 下不溢出。
- 背景：蓝色渐变 + 光斑（可换主题）；透明模式供 OBS 叠加。
- 字体：系统黑体；数字等宽；字幕描边保证可读。

## 四、状态与转场

| 状态 | 触发 | 表现 |
| --- | --- | --- |
| 专心工作中 | 有产出/在生成 | 敲键盘、监视器滚动、绿色胶囊 |
| 摸鱼中 | 空闲 ≥N 分钟 | 托腮/发呆、倒计时环变黄 |
| 被抓 | 摸鱼时用户「查岗」/定时检查 | 惊吓表情 + 弹幕「抓到你了」 |
| 白干 | 返工/失败/重复劳动 | 统计 +1，气泡「白干了…」 |
| 吃饭/下班 | 到点（生活卡） | 离开工位/吃白饭 |
| 吃撑 | Token 超预算 | 抱肚、工资条变红 |

倒计时环语义（M3 定）：剩余「摸鱼窗口」/「下一次查岗」/「离下班」三选一，先做「下一次查岗」。

## 五、数据模型（宿主 `app_meta`，`fish:v3:live` 或并入 `day:*`）

```ts
interface LiveStageState {
  date: string
  salary: { current: number; goal: number; percent: number }
  focusMinutes: number
  wastedCount: number      // 白干
  caughtCount: number      // 被抓
  speedMultiplier: number  // 手速
  rule: string             // 员工守则（轮换）
  status: 'focus' | 'slack' | 'caught' | 'off' | 'meal'
  countdown: { seconds: number; kind: 'check' | 'break' | 'off' }
  monitorLines: string[]   // 监视器内容
  comment: { user: string; text: string } | null
  subtitle: string
  characterState: 'idle'|'happy'|'sleepy'|'caught'|'eat'
}
```

**数据来源（M3 再定）**：

| 字段 | 候选来源 | 建议 |
| --- | --- | --- |
| 工资 | 当日 Token 消耗（米粒）/ 工作事件数 | **Token 消耗 × 系数**，目标可配置；上限防刷 |
| 专注 | 有交互/有生成的分钟数 | 宿主计时，不要用系统前台时间 |
| 白干 | 失败重试、重复操作、被撤销的消息 | 宿主事件（确定性），不靠模型判断 |
| 被抓 | 摸鱼状态下用户打开窗口/发消息 | 宿主事件 |
| 手速 | 近期消息速率/打字速度 | 用消息间隔映射倍率 |
| 员工守则 | 内容卡轮换 | `resources/character/cards/rules.json` |
| 监视器 | 代码片段（内容卡）/ 真实日志（脱敏）/ Token 曲线 | M3-1 用内容卡，M3-2 接真实数据 |
| 弹幕 | 手动注入 → 本地 HTTP/WS → 平台 | 见 §六 |
| 字幕 | 模型生成短句（≤20 字）/ 本地模板 | 优先本地模板保证低延迟，模型兜底 |

## 六、技术方案

### 6.1 页面形态

- 新增路由 `/live-stage`（`PetWindow.vue` 之外的新页面），只渲染舞台组件，无标题栏。
- 打开方式：主窗口菜单「直播舞台」/ 桌宠右键；可拖到副屏。
- 竖屏窗口：`BrowserWindow` 1080×1920（按屏幕缩放），`transparent` 可切换，`alwaysOnTop` 可选。

### 6.2 推流（OBS）两种方式

| 方式 | 做法 | 阶段 |
| --- | --- | --- |
| 窗口捕获 | OBS 捕获「直播舞台」窗口（Chromium 窗口采集），简单 | M3-1 |
| 浏览器源 | 新增只监听 `127.0.0.1` 的静态 HTTP 服务（token 鉴权），OBS 浏览器源加载 `http://127.0.0.1:<port>/live-stage?token=…`，可透明 | M3-2 |

> 安全：HTTP 只绑 loopback；token 每次启动随机；不做公网监听。

### 6.3 弹幕接入

| 阶段 | 方案 |
| --- | --- |
| M3-1 | 页面内置「测试弹幕」输入框（开发/演示用），不接平台 |
| M3-2 | 本地回环 API：`POST /live/comment {user,text}`，供外部脚本/机器人推送；页面轮询或 SSE |
| M3-3 | 平台接入（B站直播开放平台/抖音）——依赖平台资质与第三方工具，单独评估，绝不放进 M1/M2 |

### 6.4 性能与实现约束

- 动画用 CSS transform/opacity；数字用 `requestAnimationFrame` 节流，不要每帧触发 Vue 响应式更新。
- 监视器打字机效果用 30–60ms/字，行数上限 15 行；滚动不重排整页。
- 字幕 ≤2 行，超出截断；弹幕队列 ≤10，按时间轮播。
- 图片/字体预加载；透明模式下禁用大面积半透明模糊（OBS 性能）。
- 全部数据来自宿主 IPC 推送（`live:state`），页面不直接读文件、不调模型。

## 八、待定问题

1. 竖屏 9:16 还是横屏 16:9？（截图是竖屏；B站/抖音直播常用竖屏）
2. 工资口径：Token 消耗、工作事件、还是纯节目效果（固定脚本）？
3. 是否要观众可互动（送礼加薪/点歌/弹幕触发动作）——涉及平台权限与合规，M3 再定。
4. 平台：B站直播 / 抖音 / 视频号 / 纯本地演播？决定了弹幕接入方式。
5. 是否需要「真人出镜」合成（摄像头/虚拟形象）——不做，保持 2D Q 版。
