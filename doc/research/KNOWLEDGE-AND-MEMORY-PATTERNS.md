# 可借鉴的工程模式：表情知识库 / 冷档记忆 / 夜间回顾 / 记忆纠错

> 只写「我们准备怎么用」，不复制上游代码或文档原文。来源与许可见 `README.md`。

## 一、表情/动作知识库（借鉴 nekowhale 的 schema）

### 1.1 我们的数据结构（只标注自己的原创六态立绘）

```json
{
  "schema": "fish-emotion-kb/1",
  "emotions": ["开心","喜欢","害羞","得意","疑惑","无语","难过","生气","疲惫","搞怪","拒绝","打招呼","卖萌","其他"],
  "actions": [{
    "id": "fish/idle-01",
    "asset": "art/idle-01.svg",
    "emotion": "开心",
    "tags": ["打招呼","元气"],
    "use": "她心情好、想主动找你说话时",
    "desc": "本鱼晃着尾巴，眯眼笑",
    "dir": "",
    "unlockStage": 0
  }]
}
```

- 与 nekowhale 的差异：我们只有**一套原创六态**，先不追求 322 张；字段沿用其「情绪 + 标签 + 使用场景 + 描述 + 方向」结构，未来接用户导入素材包时直接复用。
- **方向 `dir`** 预留给「双人/互动」表情（如和 GPT娘），但 M1 不做双人。

### 1.2 回复标记协议（借鉴 `[sticker:名字]`）

- 模型回复里可带轻量标记：`[emotion:开心]`、`[emotion:摸鱼]`。
- 宿主解析：**从气泡文本里剥离标记**，映射到六态/动作；标记不展示给用户，也不进记忆。
- 为什么不把图片塞给模型：省 token、避免多模态依赖、避免模型「看见自己的图」产生循环。
- 与 OpenClaw 的关系：标记只是文本约定，不要求 OpenClaw 插件；宿主解析即可。

### 1.3 内容卡与模板（M2）

- 本地模板玩法（想/举牌/上联/下联/抱）不画新图就能出梗，用于聊天彩蛋和直播弹幕回应。
- 模板生成在宿主本地完成（SVG 叠字），不调用模型；文字内容走内容审核（C09）。

## 二、冷档记忆（借鉴 astrbot，只借思路）

目标：**保证「她记得的事」有原文可查、可纠正、可审计**，而不是一堆模型自由发挥的摘要。

| 规则 | 我们的落地 |
| --- | --- |
| 只追加、不覆盖 | `memory/YYYY-MM-DD.md` 当天只 append；Obsidian 日记一天一篇，已存在改 `update_note` |
| 按日分文件 | workspace `memory/` + Obsidian `大肥鱼/日记/` 同构 |
| 分块 + 哈希 | 长日记按 1200 字分块（可选），frontmatter 带 `source`；M1 先不做内容哈希，M2 再加 |
| 落盘前过滤秘密 | C09 的 `redactSecrets()`：Key/密码/Cookie/授权链接/身份证/手机号模式，命中即打码 |
| 权限最小化 | 只在自己的 data 目录；日记不进日志、不进错误详情 |
| 检索预算 | `memory_search` / Obsidian 检索每天有次数与间隔上限（C07 记账），避免刷爆 embedding |
| 例外 | 用户明确要求「记住这个」→ 立即写，不受预算限制 |

## 三、夜间回顾（借鉴 astrbot 的 05:00 门控）

| 规则 | 我们的落地（C07） |
| --- | --- |
| 固定时间窗 | 默认 23:00（用户可改），窗口 ±60 分钟；错过不补 |
| 安静条件 | 免打扰时段内不跑；用户最近 30 分钟在聊天 → 跳过，等下一轮 |
| 每天最多一次尝试 | `day:date.memoryDone` 幂等；失败最多 3 次、间隔 ≥5 分钟 |
| 材料预算 | 最多取 3 段当天材料（对话摘要 + 生活卡 + 关系事件），≤600 字日记，≤500 token 输出 |
| 出处强制 | 日记里「记住的事」必须带 `source`（日期 + 会话键），可被用户点开核对 |
| 失败不重试风暴 | 超时/格式异常只记状态，不循环重试；用户可手动「补写今天」 |
| 不打扰 | 写日记全程不发消息、不弹窗、不唤醒桌宠 |

## 四、记忆纠错（借鉴 astrbot 的更正流程）

触发：用户说「不是这样」「我什么时候说过」「你记错了」。

流程：
1. 她先检索命中的记忆条目（`大事记` / `约定` / `关于你/`），把原文拿出来给用户看（可折叠）。
2. 用户给出明确更正（至少一句完整的话）。
3. 宿主写一条「更正记录」：`{targetId, oldVersion, newText, quote, at}`，旧条目保留（**不删除**），标 `superseded`。
4. 新条目带 `source: correction`，下次检索优先新条目。
5. 重要条目（关系里程碑、承诺）更正后进「待确认」，用户点一下才生效。

> 不做：模型自己决定「删除记忆」。删除只能由用户 `character:reset` 或设置页逐条删除。

## 五、知识服务治理（借鉴 fat-whale，只借结构）

如果以后做「共享记忆/内容包」或远端知识服务（M2+）：

1. **安装 ID**：本机生成随机 key，服务端只存哈希，回发稳定 ID；ID 不进 URL/日志/模型上下文。
2. **限额**：每个 ID + IP 滚动窗口；429 带 `Retry-After`，不循环重试。
3. **审计不存正文**：只存 ID、IP、时间、状态、是否获准；查询正文不落审计库。
4. **投稿/候选**：schema + provenance 必填 + 冷静期 + 独立审核 + 内容哈希；修订重新排队。
5. **不编造**：没命中就返回空，明确「没想起来」，不用别的条目顶替。

> M1 只做本地版：Obsidian + workspace 双写；以上规则先写进 C07/C09 的验收清单，M2 再上服务化。

## 六、对 C07/C09 的具体增补（已并入 PLAN）

- C07 增加：写前 `redactSecrets()`；日记「出处强制」；检索预算记账；失败风暴保护；「补写」手动按钮。
- C09 增加：更正流程（版本 + 审计 + superseded）；删记忆只能用户操作；公私有上下文隔离（私聊记忆不进入直播/公开内容）。
- 验收用例：密钥不落盘、更正保留审计、夜间门控（最近聊天则跳过）、每天只一次、失败不重试、私聊内容不进公开。
