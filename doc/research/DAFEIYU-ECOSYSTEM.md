## 一、dsh-nekowhale-stickers（Loping151）

**形态**：给 DeepSeek Harness（DSH）用的**表情知识库插件**：322 张表情逐张标注场景/情绪/梗/方向，配 6 个本地模板；同时提供 MCP server、CLI、cordis 服务、公开 JSON。

**许可**：代码 Apache-2.0（需保留 NOTICE）；`meta/` 知识库数据 CC BY-NC 4.0（需署名、禁止商业用途）；图片版权归作者（B站 可以叫我云大人/雾雪，kiriyuki.com 制作）。

**数据结构**（`sticker-kit/1`，我们最值得借鉴的部分）：

```json
{
  "schema": "sticker-kit/1",
  "emotions": ["开心","大笑","喜欢","害羞","得意","兴奋","惊讶","疑惑","思考","无语","难过","哭","生气","害怕","疲惫","赞同","拒绝","打招呼","感谢","道歉","卖萌","搞怪","嘲讽","安慰","其他"],
  "stickers": [{
    "id": "大肥鱼/10N01_猫猫搓手",
    "hash": "4a44767ab58b",
    "text": "",
    "emotion": "兴奋",
    "tags": ["期待","搓手","跃跃欲试"],
    "use": "期待好事发生或迫不及待想试试时",
    "desc": "大肥鱼眯着眼睛微笑，脸颊泛红，两只猫爪在胸前反复搓动……",
    "meme": "（梗出处，可空）",
    "dir": "大肥鱼→GPT娘",
    "en": "Rubbing paws in eager anticipation"
  }]
}
```

**可借鉴**：
1. **「情绪 + 使用场景 + 标签 + 梗出处 + 方向」五元组**比单纯的图片文件名有用得多：模型可以按情绪检索、桥接层可以按方向拼双人图。
2. **回复标记协议**：模型在纯文本回复里写 `[sticker:名字]`（或情绪词），桥接层 `parseReply()` 拆成文字 + 图片，不把图片塞进模型上下文（省 token，也避免多模态依赖）。
3. **6 个本地模板**（想/举牌/上联/下联/抱）：无需画新图就能生成「文字表情包」，非常适合直播互动和聊天彩蛋。
4. **自选/黑白名单**、按情绪随机去重、懒下载与增量同步：内容运营的完整闭环。
5. **网页桌宠用跨域 iframe 隔离**：桌宠不接触宿主会话，配置项可关。这个隔离思路可以借鉴到我们的桌宠窗口（独立 preload/无 Node）。

**不采纳**：DSH 插件契约（`dsh plugin add` / cordis）与我们 Electron 宿主不兼容；图片与 `meta/` 数据不打包（NC）；不依赖 kiriyuki.com 运行时。

## 二、CleverWing/fat-whale-library

**形态**：DSH 插件 + **共享视频知识服务**（REST + MCP）。按主题检索视频，或用 BV 精确读取梗概/关键词/分时段摘要；服务端集中维护，客户端只带一个自动领取的安装 ID。另带投稿审核流程。

**许可**：代码 MIT；图像 CC BY-NC-SA 4.0。

**可借鉴的治理设计**（不是内容）：
1. **安装 ID 与隐私边界**：插件本机生成 64 位 key，服务端只存哈希，回发稳定 `DFY-` ID；ID 不进 URL、不进口志、不给模型看完整值。→ 我们的记忆同步/远端能力若做，照此处理。
2. **限额与审计**：每个 ID + 每个来源 IP 滚动窗口限额；审计库只存 ID、IP、状态、是否获准，**不存查询正文**；429 带 `Retry-After`，禁止循环重试。→ 我们的记忆整理任务、直播评论拉取都应有同类预算。
3. **契约与「不编造」**：请求只有 `query`/`bvid`，无匹配返回 `items:[]`、`found:false`，**不允许用别的视频顶替**；主题视图不返回全部时间段。→ 对应我们的「记忆检索宁可说没想起来，也不许编」。
4. **投稿审核**：`schema_version` + 必填 provenance + 24 小时冷静期 + 独立管理员五项确认（来源/内容/原创/无秘密/无指令）+ 内容哈希 + 修订重新排队。→ 对应我们 C07 的「重要记忆候选确认」与 M2 的关系档案导出/纠错。
5. **字段预算**：单视频 256 KiB 投影预算，超预算降级为 compact，不静默截断。→ 我们的内容卡/记忆注入也应设预算。

**不采纳**：视频知识库本身（与角色无关，且是 DSH 插件）；不复制其文档原文。

## 三、FigaroGao/astrbot-fish-capabilities

**形态**：AstrBot（QQ/NapCat）上的大肥鱼能力扩展：意图接话、B站阅读/互动、天气、战绩、表情、长期记忆适配、统一时间表、语音识别。另有一个桌面陪伴仓库 `Xiaojing-Screenmate`（GitHub 404，可能已改名/私有，未能核验）。

**许可**：**AGPL-3.0**。→ **代码一行都不能拷进 MIT 项目**；文档原文也不搬；只吸收设计思路。

**值得吸收的设计（只写思路，不抄实现）**：
1. **冷档（cold archive）**：只捕获主人私聊文字，按香港日期分目录，原文最多 1200 字分块、SHA256、只追加不覆盖；文件权限 0400/0600/0700；落盘前过滤 Key/密码/Cookie/授权链接。
2. **按线索回忆**：`fish_recall(search)` 每次只返回 1–2 段、每段 ≤1200 字；查询≥5 分钟间隔、同线索 1 小时不重复、每天最多 12 次；明确提示「片段会进入当前云端模型请求」，不宣称不出本机。
3. **日记更正**：需要真实 ID + 版本号 + 主人当前消息里至少 4 字明确更正原话 + 独立模型审查 + 保留审计、版本递增；不改原文冷档。
4. **夜间回顾**：每天 05:00，只在 03:00–08:00、设备心跳有效、主人近 30 分钟无聊天时运行；每晚最多一次模型尝试、最多 3 段材料、≤600 字日记、≤500 token；**出处必须含片段 ID + 可逐字核对的短引用**；超时/格式不符不循环重试；不唤醒、不弹窗、不发 QQ。
5. **统一时间表**：提醒/天气/商店/刷站/检查任务共用一个调度器，自然语言创建；暂停/恢复/取消。→ 对应我们 C06 的主动性调度与 C07 的记忆任务，不能各造一套定时器。
6. **公私有隔离**：引用冷档/日记的私聊会话标记为私有上下文，公开内容（B站评论/动态）不得引用；群聊/非主人不能访问冷档。→ 对应我们 C09 的隐私边界。
7. **记忆纠错与审计**：检索旧记忆、独立审查、版本校验、保留审计。→ 对应我们 `大事记/约定` 的更正流程。
8. **语音边界**：只做 ASR（听懂），不自动发语音；TTS 另配。→ 对应我们「入站语音需 STT，否则诚实说没学会听」。

**为什么对我们特别有价值**：它把「陪伴型角色长期运行」踩过的坑写成了规则：夜间门控、回忆预算、更正审计、公私隔离、防重复重试。我们不需要自己从零试错。

## 四、DSH 与 OpenClaw/4.0 的生态错配（重要）

- 现成大肥鱼资产（表情包、桌宠、主题、插件）绝大多数是 **DSH（DeepSeek Harness）插件**，契约是 `dsh plugin --profile ... add` + `cordis.patch.yml`。
- 我们的 4.0 是 **Electron 宿主 + OpenClaw 网关**，没有 cordis，不能装 DSH 插件。
- 能跨栈复用的是：**人设文本、表情元数据 schema、回复标记协议、模板玩法思路、图片资源（仅自用/导入）**，不是插件本身。
